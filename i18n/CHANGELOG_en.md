## 2026-09-05 (round 9)
- Fixed "pause" losing the last buffered fragments and the echo dedup: the pause path reset the incremental-ASR state the moment its own flush found no audio remaining — but that only proves *this* pause has no segment to hand over, not that no earlier vad_flush (a natural VAD split, a silence-feed flush, an earlier hand-off) is still queued unconsumed. That item's consumer then read a cleared `_interim_active` and took the plain recognition path: the buffered short fragments (their audio already trimmed, the text the only remaining copy) never reached the record, and the echo tail stopped working. pause() no longer cleans up on its own: the whole "flush → enqueue → cleanup decision" runs inside the session boundary fence (the producer fence), a successful audio hand-off is reset by the consumer's existing cleanup, and when no audio was enqueued a no-audio cleanup marker is appended to the queue — the recognition thread is a single-consumer FIFO, so the marker runs strictly after every pre-pause item (including an interim pass still writing state) and before any audio enqueued after the resume, and its handler's existing cleanup performs the one reset. "The pre-pause remainder finishes; the next utterance starts clean" now holds by ordering, not by resetting early under a consumer. Only when the marker itself is refused (a stop already begun, a closing generation, the queue rejecting even after dropping a victim) does pause reset inline as the bounded last resort. The Qt main thread only ever does short local work (a VAD flush, non-blocking puts, counter registrations) and never waits for the queue to drain
