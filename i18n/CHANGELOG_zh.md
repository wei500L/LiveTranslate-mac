# 更新日志

## 2026-09-01
- 修复基准测试按钮可能永久失灵的问题: 某个模型配置缺少名称（或汇总阶段抛错）时，异常会顺着线程池传出来把整个基准测试线程打死，收尾的 `__DONE__` 永远发不出去 —— 而按钮正是靠它重新启用的，只能重启应用。现在无论哪一步失败都保证收尾，单个模型的错误也只记为该模型失败、不影响其余模型
- 修复新增模型对话框静默丢弃不完整条目的问题: 名称或模型 ID 留空时，对话框正常关闭，但列表处理逻辑会把这个条目整个丢掉 —— 用户填完表单、点了确定，什么都没发生。现在必填项留空会提示并留在对话框内
- 修复在悬浮窗改目标语言后，再改任意面板设置就会被改回去的问题: 改语言时写的是 `get_settings()` 返回的**副本**，文件存对了但面板自己的状态没跟上，下一次自动保存又把旧值写了回去; 面板新增 `update_setting()` 作为外部写入的唯一入口
- 修复字幕行列表在缺 `lines` 配置时显示与操作不一致: 列表用默认行填充，而增删改和上下移都退回到空列表，于是界面上有行、任何操作都对不上; 同时补齐「上移」缺失的上界检查
- 修复增量识别的回声去重从未生效: 提交的文本总是完整句子、总以句末标点结尾，而匹配时带着那个标点，新识别结果永远不以标点开头，因此这段去重逻辑一次都没触发过; 现在忽略尾部标点后可以识别真实回声，同时刻意保留单词级重复 —— 讲课时下一句以上一句的关键词开头很常见，删掉那个词会让句子失去主语，而重复一个词只是读起来啰嗦
- 修复 VAD 静音模式切换依赖无关设置项的问题: 从「自适应」切到「固定」时，静音阈值只在 `silence_duration` 恰好同时出现在设置字典里才会重算，否则会继续沿用自适应压低后的值
- 修复暂停后恢复会把两段语音拼成一句的问题: 暂停时 VAD 缓冲原封不动保留，恢复后的音频直接接在暂停前那半句后面，中间跨着任意长的时间跳切，输出一条前言不搭后语的字幕; 现在暂停会把在途的半句交给识别线程正常出字幕，缓冲清空，恢复后从干净状态开始
- 修复改任意设置都会重排全部字幕的问题: 控制面板每次自动保存都发送全量设置字典，样式因此被无条件重新应用 —— 满 50 条消息时每次约 59 毫秒，跑在界面线程上; 调一下 VAD 滑块或勾个复选框都会触发。现在样式没变就直接跳过
- 修复增量识别下短应答可能被静默丢弃的问题: 已缓冲的短句（如「да」「好的」）会先并入本次片段文本，再一起接受噪声过滤; 如果这次片段本身只有噪声而尾部又超过 2 秒，整条会被当作噪声丢掉 —— 用户说了话却什么都不出现。现在噪声过滤只判断本次片段自己的识别结果，早前已通过检查的缓冲内容照常输出
- 修复 ASR worker 意外退出后识别永久停止的问题: worker 被杀或崩溃后，客户端抛的是基类异常，而管线的恢复分支只捕「worker 已退出」这一类，于是每一段音频都撞同一个错误、永远不触发重启; 实测杀掉 worker 后 12 段只识别出 3 段并从此静默，修复后自动重启并识别出 11 段（只丢被杀瞬间正在处理的那一段）
- 修复会议中途切换翻译模型会让记录停止更新的问题: 切换时在途的那条翻译会被丢弃，但此前既不收尾转录也不收尾悬浮窗条目; 由于记录按说话顺序释放，那一条会把它之后的所有条目全部堵住（实测 3 条只写出 0 条），悬浮窗对应消息也永远停在「翻译中」

## 2026-08-31
- 修复模型基准测试与实时翻译在「禁用思考」上仍会分叉的问题: `Translator` 自身的 `no_think` 默认是 False，而每个调用方都传 True，因此任何直接构造 Translator 的代码（包括基准测试）在配置未显式设置 `thinking_style` 时会静默拿到「不发送任何参数」，而实时路径拿到的是「自动识别」—— 恰好是基准测试用来诊断的那个参数; 现在两条路径共用同一个构造入口 `translator_from_model_config()`，不再各自维护一份参数清单
- 补充配置说明: `config.yaml` 的空 api_key、上下文轮数、max_tokens 与采样温度都写明了实际语义；模型编辑对话框的「上下文轮数」提示补充了两个容易踩的点（提示词含 `{context}` 时改为嵌入而不发多轮；翻译专用模型对两种形式反应不同）；「模型连接超时」新增提示，说明首次请求通常明显更慢
- README 增加「排查问题」一节，介绍用 `debug_pipeline.py` 回放音频文件定位故障
- 本地 HY-MT 模型改用上下文多轮与贪心解码: 之前 `no_system_role` 的模型会**静默忽略** `context_turns`（设成 3 也没有任何上下文，且无提示），现在历史会以真正的多轮消息发送 —— 实测能正确还原代词指代（「现在求出它」→「现在求出这个函数的导数」），一整段课堂 8/8 稳定，prompt 仅多约 60 token; 注意这只在「多轮消息」形式下成立，把同样的历史贴进提示词文本仍会让模型续写（0/3）
- 本地模型改为贪心解码（temperature 0.7 → 0.0）: 同一句话重复翻译，之前 4 次里只有 2 次结果一致，现在 4/4 完全一致，质量相当且更快（平均 0.39s vs 0.49s）—— 字幕不该在同一句话上来回变。`top_k` 随之移除（贪心下无意义），`repetition_penalty` 保留作跑飞保护
- 修复本地 HY-MT 模型输出提示词而非译文的问题: 该模型是翻译专用模型而非指令模型，面对多行指令块会「续写」而不是执行 —— 实测长提示词 3/3 失败（吐回提示词、用光 128 token 预算、每句约 2.5 秒），改成单行指令后 4/4 正确（每句约 0.3 秒）; 同时把 `context_turns` 归零，因为在 `no_system_role` 下上下文只能经 `{context}` 注入，而带上下文块同样会触发跑飞（0/3）。仍是旧预设提示词的配置会自动迁移，自己改过提示词的不动
- 修复退出时等待本地模型服务约 5 秒的问题: 应用和设置面板各自持有一个服务管理器，负责停止的那个从未创建过该进程，因而无法回收它，只能轮询一个僵尸进程直到超时并误报「无法结束」; 现在共用同一个管理器，退出耗时从 7 秒降到 1 秒
- 修复本地服务启动后翻译器被重复构建两次的问题（上下文历史被清空两次）
- 修复空 API key 导致应用完全无法启动的问题: `config.yaml` 默认就是空 key，而新版 openai SDK 在构造客户端时直接拒绝空 key，于是任何未配置密钥的全新安装在窗口出现之前就崩溃; 现在空 key 会当作「本地服务不校验密钥」处理（LM Studio、Ollama、本地 MLX 服务都是这样）
- 修复会议记录条目顺序错乱的问题: 翻译在 8 个线程上并发完成，此前每条译文一到就写文件，导致 all/translation 记录的顺序是「翻译完成顺序」而不是「说话顺序」; 现在按说话顺序释放，退出时也会补写尚未等到译文的条目，不再丢失
- 新增「会议记录」设置页: 列出历次会议（时间、条数、时长、ASR 引擎、翻译模型），可预览内容、导出单场记录、删除单场记录
- 会议记录内容更完整: 每条附带语种与时长，新增 Markdown 版记录，会话结束写入摘要（起止时间、总时长、语音时长、条数、使用的引擎与模型），并生成 JSON 元数据便于列表展示
- 新增调试系统: `debug_pipeline.py` 可把音频文件当作采集源喂进真实管线（VAD → ASR worker → 翻译 → 转录），完整捕获 DEBUG 日志并输出分阶段报告; 「某一环节被要求工作却什么都没产出」会判定为失败，而不是安静通过
- 修复 ASR worker 在管线启动前加载完成会被误判为「已被更新的切换取代」而丢弃的问题
- 修复退出时控制面板的后台线程（缓存扫描、MLX 探测）可能在仍在运行时被销毁的问题
- 退出日志不再重复打印两次「Pipeline stopped」

## 2026-08-30
- 修复退出可能挂起或留下残留进程的问题: 停止流程此前用阻塞式队列写入投递停止信号,队列满且识别线程已退出时会永远等待; 现在停止是幂等且有界的,任一清理步骤失败也会继续回收后续的线程、转录文件、识别 worker 和本地服务
- 修复识别 worker 正在长耗时转写时,退出或切换引擎要等最长 120 秒的问题: 客户端的请求锁与生命周期锁此前是同一把,退出被阻塞在进行中的转写后面; 现在退出会立即中止 worker,界面在一两秒内响应; 模型加载中途切换引擎同样可以立即中止
- 修复识别 worker 已消失但状态仍显示"就绪"的问题: 进程自行退出或句柄已关闭时会被误判为可复用,后续请求既不恢复也不报错
- 修复"删除全部模型并退出"可能删不干净的问题: 此前直接退出 Qt 绕过了流水线清理,识别 worker 仍持有模型目录; 现在先完整停止并确认 worker 已退出再删除,删除在后台进行并显示进度,失败路径会在界面上列出
- 修复 Ctrl-C 在信号处理器里执行数秒清理的问题, 连按两次不再产生重复清理
- 修复启动后 500 毫秒内点击暂停或退出会被延迟启动回调覆盖的问题; 托盘与悬浮窗在真正启动前不再显示"运行中"
- 修复选中 HY-MT 模型时点击模型列表卡顿约 2 秒的问题: 部署状态、环境状态和服务状态此前在界面线程上同步派生子进程和发起 HTTP 请求; 现在全部在后台线程完成,界面只读缓存值
- 修复 HY-MT 服务未启动时每 5 秒清空一次翻译上下文的问题: 此前每轮探测都会重置翻译器; 现在只在"可用→不可用"的状态跳变时执行一次,自动重启也有退避和次数上限,达到上限后提示手动启动
- 修复模型下载静默期间取消无效的问题: 取消此前只在子进程输出新行时才被检查,长时间无输出的下载无法中断; 现在取消随时生效并终止整个进程树,不再残留进程或 pid 文件
- 修复下载过程中退出后控制台不再输出日志的问题: 被替换的 sys.stderr 只在成功分支恢复,中途退出会让它永久指向已销毁的窗口; 现在任何退出路径都会恢复
- 修复准备 HY-MT 模型会向应用自身运行环境安装依赖、并可能删除服务正在使用的模型目录的问题
- 修复首次启动向导写入的 VAD 阈值与 config.yaml 不一致的问题 (0.3 vs 0.5)
- 修复连续短句字幕丢失中间句的问题: 字幕窗口此前收到新句子会取消待显示的上一句,现在按到达顺序排队显示
- 修复重复输出检测受流式开关影响的问题: 非流式路径此前跳过检测; 同时新增对"开头正常、后面开始复读"的尾部检测
- 修复翻译服务不可达时每句要等两倍超时的问题: 流式请求的失败回退此前捕获所有异常并整句重试
- 修复增量识别把同一句短应答重复输出的问题: 短句被缓冲时不推进音频裁剪与回声去重状态,下一轮会重新识别出同样的内容
- 修复噪声片段被丢弃后,残留的增量状态串到下一段语音的问题
- 修复删除模型后配置、悬浮窗和运行中的翻译器可能指向不同模型的问题: 删除活动模型之前的条目会使索引整体前移
- 修复模型基准测试与实际翻译请求不一致的问题: 现在复用同一套请求组装逻辑(思考模式、覆盖参数、extra_body、JSON 模式、角色拆分); 对思考模型或不可达端点跑基准不再崩溃或耗时翻倍
- 修复长字幕换行在界面线程上的二次方开销,以及某个目标语言译文为空时出现前导分隔符
- 修复反复切换到缓存页会并发派生多个模型目录扫描线程的问题
- 修复导出的对话记录在超过 50 条后静默不完整的问题: 现在明确提示只包含最近 N 条,并给出完整转录文件路径
- 修复 Windows 音频采集在队列拥塞或设备重启失败时静默停止出声的问题: 现在丢弃最旧的音频块而不是让采集线程退出,重启失败会重试并在耗尽次数后明确停止
- 修复 macOS 仅麦克风模式下终止性采集失败被当作"暂时没有数据"的问题; 三个采集后端现在对"无数据"与"终止性失败"的表达一致
- 远程 ASR 服务默认改为只监听 127.0.0.1(此前 0.0.0.0 直接暴露无鉴权的 GPU 推理端口),新增可选的共享密钥校验和请求体大小上限; `uvicorn asr_server:app` 不再因缺少配置而启动失败
- Fun-ASR-Nano 音频加载失败现在保留原始错误,不再被后续的 UnboundLocalError 掩盖
- HY-MT 服务的全部提示与错误文案、语言切换提示改为跟随界面语言
- 移除 macOS 依赖中未被使用的 pyannote-audio / torchcodec(仅长音频转写路径需要,本项目不走该路径); 新增依赖双向对称性检查,防止再出现单平台缺失

- 修复远程 ASR 服务不可用时被当作"没有语音"的问题: 服务宕机、连接超时、HTTP 5xx、返回非 JSON 现在都会进入与本地 worker 故障相同的恢复流程并显示 ASR 不可用,而不是静默丢弃音频; 合法的空识别结果仍然安静跳过
- 修复 macOS 上改动任意设置都会中断音频约 8 秒的问题: 控制面板每次自动保存都会发送全量设置,而系统音频采集未做设备相等性判断,导致设备毫无变化时也整流重启; 现在仅在设备真正改变时才切换,切换失败会恢复原设备,无法恢复时明确停止并提示
- 修复说话过程中改设置或切换 ASR 引擎可能损坏语音缓冲的问题: 界面线程绕过锁重置 VAD 状态,与采集线程并发写入时可造成缓冲区与置信度序列长度失配,进而影响切分点选择和静音判定
- 修复增量 ASR 分句库缺失时识别线程直接退出的问题: 现在降级为不分句并记录明确错误,不再拖垮整条识别链路
- `requirements.txt` / `requirements-mac.txt` 现在可独立装出可运行环境: 补充此前仅由安装脚本单独安装的 yasbd-lib、Windows 侧缺失的 socksio(socks5 代理需要),并为 transformers 补上与本地 MLX 服务一致的 <5 上界
- 修复测试与发布流程: 启动器提示文案回归导致测试失败、CI 依赖不全导致部分测试无法收集、Windows 发布作业未依赖测试作业(测试失败仍会发布); 现在两个平台的发布均受测试门禁约束,并新增断言防止该门禁再次缺失
